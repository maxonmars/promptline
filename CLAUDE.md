# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

`promptline` — CLI для диалога с LLM через DeepSeek API. Два режима: с аргументом — один вопрос
и выход, без аргумента — интерактивный диалог через `node:readline/promises`. Флаги и слэш-команды
задают формат ответа, лимит длины и условие завершения. Тестов, линтера и CI нет.

## Команды

```bash
npm install
npm run dev                              # интерактивный диалог без ограничений
npm run dev -- --strict                  # тот же диалог с пресетом ограничений
npm run dev -- "свой вопрос"             # один вопрос; -- обязателен, иначе npm съест аргументы
npm run dev -- --help                    # список флагов и слэш-команд
npm run dev -- --compare "вопрос"        # один запрос дважды: без ограничений и с ними
npm run dev -- --repeat=3 "вопрос"       # N независимых прогонов, проверка стабильности формата
npm run build && npm start               # tsc в dist/, затем node dist/index.js
```

Нужен Node.js 20+ и `.env` с `DEEPSEEK_API_KEY` (шаблон — `.env.example`).

## Архитектура

DeepSeek отдаёт API, совместимый с OpenAI, поэтому используется официальный пакет `openai`
с подменённым `baseURL` на `https://api.deepseek.com`. Модели задаются строкой в
`DEEPSEEK_MODEL`: `deepseek-v4-flash` (по умолчанию) или `deepseek-v4-pro`.

Четыре модуля: `index.ts` — режимы запуска и вывод, `options.ts` — разбор флагов, слэш-команды
и сборка системного промпта, `formats.ts` — описания форматов и проверка ответа, `ask.ts` —
единственный вызов API.

Системное сообщение не лежит в `history`, а подставляется в голову запроса на каждый вызов —
поэтому `/format` и другие переключатели действуют со следующей реплики. `history` копится
в памяти и уходит в API целиком, что даёт контекст и линейно удорожает длинную сессию. Реплики
дописываются только после успешного ответа, так что вопроса без ответа там не остаётся.

Два пресета в `options.ts`. `RAW_OPTIONS` — свободный текст без лимитов и стоп-маркера, это
стартовый режим по умолчанию. `STRICT_OPTIONS` — `json`, 60 слов, стоп-секвенция; включается
флагом `--strict` или командой `/strict`. Явные флаги применяются поверх выбранного пресета.

Неочевидное: `--compare` тоже стартует со `STRICT_OPTIONS`, даже без `--strict`. Левую колонку
он всегда берёт из `RAW_OPTIONS`, правую — из текущих options, поэтому при raw-старте обе
колонки оказались бы одинаковыми и демонстрация превратилась бы в два одинаковых ответа.
`dropStopForJson` сверяется со `STRICT_OPTIONS.stopMarker`, отличая пресетный маркер от заданного вручную.

Три структурных формата (`json`, `md`, `yaml`) описывают один контракт: `summary` плюс `items`
с полями `order`, `name`, `weight`. Сменить предметную область — значит переписать `instruction`
и `ITEM_FIELDS` в `formats.ts`.

ESM: `"type": "module"` + `module: "nodenext"`. Top-level `await` используется напрямую,
относительные импорты внутри проекта потребуют расширения `.js`.

## Особенности reasoning-моделей

`deepseek-v4-flash` пишет рассуждение в `reasoning_content` и только потом ответ. Отсюда четыре
решения, которые иначе выглядят произвольными.

`max_tokens` покрывает рассуждение вместе с ответом, а его длина гуляет от 200 до 2000+ токенов
на одном и том же вопросе. Низкая крышка даёт пустой `content`, а не обрезанный, поэтому
`maxTokens` по умолчанию `null`: длину задаёт `maxWords` через промпт. Крышка осталась явным
флагом `--max-tokens`, её эффект виден по `finish_reason: length`.

Стоп-секвенция сверяется и с текстом рассуждения: если модель упомянет там сам маркер,
генерация оборвётся до ответа. Редко, но случается — `diagnose()` в `index.ts` распознаёт оба
вида пустого ответа и подсказывает флаг.

При `format: "json"` стоп-маркер снимается функцией `dropStopForJson`: `response_format`
уже гарантирует закрытый объект, а маркер после него сломал бы `JSON.parse`.

`temperature` у этих моделей ничего не решает: thinking mode включён по умолчанию, а в этом режиме
DeepSeek игнорирует `temperature`, `top_p`, `presence_penalty` и `frequency_penalty` — принимает
без ошибки, но не применяет (https://api-docs.deepseek.com/guides/thinking_mode/). Поэтому
`DEFAULT_OPTIONS.temperature` — `null`; флаг `--temperature` остался явным, а `temperatureNote()`
в `index.ts` предупреждает, если параметр всё же задали и в ответе было рассуждение.

Сделать температуру рабочей может только явное отключение thinking — флаг `--thinking=off`
(`options.thinkingEnabled`, поле `thinking: { type: "disabled" }` в запросе, типов для него в SDK
нет, поэтому в `ask.ts` объявлен локальный тип `DeepSeekParams`). Обе связки не сливаются в одну:
`--temperature` не включает `--thinking=off` сама по себе — каждый флаг делает ровно то, что называет.
