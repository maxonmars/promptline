# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Что это

`promptline` — CLI для диалога с LLM через DeepSeek API. Два режима: с аргументом — один вопрос
и выход, без аргумента — интерактивный диалог через `node:readline/promises`. Флаги и слэш-команды
задают формат ответа, лимит длины, условие завершения и способ рассуждения. Линтер — Biome, тесты — Vitest, CI на GitHub Actions.

## Команды

```bash
npm install
npm run dev                              # интерактивный диалог без ограничений
npm run dev -- --strict                  # тот же диалог с пресетом ограничений
npm run dev -- "свой вопрос"             # один вопрос; -- обязателен, иначе npm съест аргументы
npm run dev -- --help                    # список флагов и слэш-команд
npm run dev -- --compare "вопрос"        # один запрос дважды: без ограничений и с ними
npm run dev -- --repeat=3 "вопрос"       # N независимых прогонов, проверка стабильности формата
npm run dev -- --strategy=all --expect="X" "задача"   # четыре способа рассуждения и сравнение
npm run dev -- --thinking=off --temperature=all --repeat=5 "вопрос"   # 0 / 0.7 / 1.2 и разброс ответов
npm run dev -- --model=all --repeat=5 --expect="X" "вопрос"   # три уровня модели и сравнение
npm run build && npm start               # tsc в dist/, затем node dist/index.js
npm run lint                             # biome check
npm run typecheck                        # tsc --noEmit над src и tests
npm test                                 # vitest run
npm run test:coverage                    # vitest run --coverage, пороги из vitest.config.ts
```

Нужен Node.js 24+ (исполняет TypeScript сам) и `.env` с `DEEPSEEK_API_KEY` (шаблон — `.env.example`).

## Проверки

`lint`, `typecheck`, `test:coverage` и `build` гоняет CI (`.github/workflows/ci.yml`) на каждый PR
и push в `main`. Прекоммит-хук `.githooks/pre-commit` повторяет линтер по застейдженным файлам
и тайпчек; подключается скриптом `prepare` при `npm install`. Хук — подстраховка, а не замена CI:
он обходится `--no-verify` и не существует до первой установки зависимостей.

Biome в хуке запускается без `--write`: автофикс правит файл целиком, включая незастейдженные
куски, и в коммит ушло бы не то, что показывал `git diff --staged`. `npm run build` держится в CI
отдельным шагом — эмит `.ts` → `.js` в импортах тайпчеком не покрыт.

## Тесты

Файл на модуль плюс `cli.e2e.test.ts`. API не вызывается ни в одном: `tests/support/stub-client.ts`
подставляет объект с тем же `chat.completions.create`, отдаёт заготовленные ответы по порядку
вызовов и хранит параметры каждого — на них проверяется сборка запроса, а `Error` в списке ответов
роняет соответствующий вызов. Фикстуры `AskResult`/`SolveResult` — в `tests/support/fixtures.ts`.

`cli.e2e.test.ts` запускает `src/index.ts` дочерним процессом и проверяет только то, что случается
до первого запроса к API: справку, ошибки разбора флагов, отказ без ключа. Рабочий каталог —
временный, иначе `.env` репозитория дал бы ключ там, где проверяется его отсутствие. По той же
причине в `env.test.ts` подменён `process.loadEnvFile`.

Пороги покрытия заданы в `vitest.config.ts` и падают вместе с шагом CI. `src/index.ts` из отчёта
исключён: он исполняется только в дочернем процессе e2e, куда инструментация не доходит, и в
отчёте был бы нулём независимо от того, проверен запуск CLI или нет.

## Архитектура

DeepSeek отдаёт API, совместимый с OpenAI, поэтому используется официальный пакет `openai`
с подменённым `baseURL` на `https://api.deepseek.com`. Модель задаётся строкой в `DEEPSEEK_MODEL`
(`deepseek-v4-flash` по умолчанию или `deepseek-v4-pro`) либо флагом `--model=NAME`, который
перекрывает `.env` на время запуска.

Девять модулей: `index.ts` — режимы запуска, ввод-вывод и счётчики прогонов, `report.ts` — строки
отчёта и сводные таблицы, `env.ts` — чтение и проверка переменных окружения через Zod,
`options.ts` — разбор флагов, слэш-команды и сборка системного промпта, `formats.ts` — описания
форматов и проверка ответа, `strategies.ts` — описания способов рассуждения, `models.ts` — уровни
модели для `--model=all`, `solve.ts` — один способ целиком, `ask.ts` — единственный вызов API.

`report.ts` не печатает, а возвращает строки: `index.ts` — top-level скрипт с `process.exit`
и readline, импортировать его в тесте нельзя, и вместе с ним были бы непроверяемы инварианты
сводных таблиц. Счётчики (`StrategyTally`, `TemperatureTally`, `ModelTally`) объявлены там же,
а наполняет их `index.ts` по ходу прогонов.

Системное сообщение не лежит в `history`, а подставляется в голову запроса на каждый вызов —
поэтому `/format` и другие переключатели действуют со следующей реплики. `history` копится
в памяти и уходит в API целиком, что даёт контекст и линейно удорожает длинную сессию. Реплики
дописываются только после успешного ответа, так что вопроса без ответа там не остаётся.

Два пресета в `options.ts`. `RAW_OPTIONS` — свободный текст без лимитов и стоп-маркера, это
стартовый режим по умолчанию. `STRICT_OPTIONS` — `json`, 60 слов, стоп-секвенция; включается
флагом `--strict` или командой `/strict`. Явные флаги применяются поверх выбранного пресета.

Неочевидное: `--compare` тоже стартует со `STRICT_OPTIONS`, даже без `--strict`. Левую колонку
он всегда берёт из `RAW_OPTIONS`, правую — из текущих options, поэтому при raw-старте обе
колонки оказались бы одинаковыми и демонстрация превратилась бы в два одинаковых ответа.
`dropStopForJson` сверяется со `STRICT_OPTIONS.stopMarker`, отличая пресетный маркер от заданного вручную.

`json` и `yaml` сверяются одной `ContractSchema` на Zod: `summary` плюс `items` с полями `order`,
`name`, `weight`, включая типы полей — раньше json проверял только присутствие ключей, а yaml не
проверял `items` вовсе. `yaml` разбирается библиотекой `yaml`, а не регуляркой по двум ключам,
и делает это строго: обёртка в ```yaml нарушает инструкцию формата и теперь проваливает разбор,
как и у json. У `md` контракта нет — заголовки остаются substring-проверкой, а не структурой.
Сменить предметную область — значит переписать `instruction` и `ContractSchema` в `formats.ts`.

## Способы рассуждения

`strategies.ts` устроен как `formats.ts`: реестр с блоком системного промпта, пустая строка означает
«ничего не добавляем». Формат задаёт, как оформить ответ, способ — как думать. Оси не сочетаются:
схема `summary`/`items` вытесняет разбор, поэтому `ensureCompatible` отклоняет пару на разборе
аргументов и в слэш-командах, а не предупреждает. Полуприменённый способ попал бы в сравнение
как полноценный.

`meta` — единственный способ с двумя вызовами, поэтому оркестрация живёт в `solve.ts`, а `ask.ts`
остаётся одним вызовом API. Сгенерированный промпт уходит системным блоком через параметр
`extraSystem`, а пользовательским сообщением остаётся исходная задача: промпт вправе сослаться на
неё словами «приведённая задача», и подстановка его вместо вопроса оставила бы вызов без условия,
а в интерактиве — с чужой темой из `history`. Пустой первый ответ обрывает способ до второго вызова.
В `history` пишется исходный вопрос, промпт туда не попадает.

`buildSystemPrompt` ставит `extraSystem` на место инструкции способа — до блоков формата, длины и
`FINAL`. Порядок существенный: сочинённые моделью промпты заканчиваются требованием вроде «верни
только имя», и стоя последним такой текст перебивает контракт ответа рецентностью.

Сбой любого вызова приводит к `StrategyError`, который несёт уже потраченные токены и время:
у `meta` первый вызов оплачен, даже когда упал второй, и в сводке цена способа не должна занижаться.

`SolveResult` не наследует `AskResult`, а содержит его дважды (`final`, `preparation`). Агрегат
с суммой токенов обманывал бы `diagnose()` и `temperatureNote()`: те связывают `finishReason` и
`reasoningTokens` с одной генерацией. Суммарные токены лежат отдельным полем — это цена способа,
и у `metrics()` для них отдельная формулировка «за два вызова».

`--strategy=all` гоняет способы **последовательно**, хотя `--compare` рядом использует `Promise.all`.
Параллельные вызовы делят общий rate limit, из-за чего колонка времени перестаёт что-либо измерять;
плюс каждый способ обёрнут в свой `try/catch`, и сбой не роняет уже оплаченные ответы остальных.

`--expect` сверяет не весь текст, а значение строки `FINAL:`, которую требует `FINAL_CONTRACT`,
и сверяет целиком, а не подстрокой. Обе строгости закрывают ложные попадания: разбор всего ответа
засчитал бы верное значение из промежуточных прикидок при неверном итоге, а подстрока засчитала бы
«не Даша» как «Даша». Ложный промах виден в напечатанном ответе, ложное попадание — нет.

Контракт включается вместе с `--expect` или `--temperature=all` и добавляется всем способам
одинаково, включая `direct`, иначе сравнение нечестно. Отсутствие строки — не промах, а
неизмеренный прогон: в знаменатель доли попаданий он не входит и печатается отдельной строкой. В интерактивный режим
эталон не передаётся вовсе (`solve(..., null)`): контракт там не запрашивался, и диагностика
«строки FINAL нет» была бы ложной.

Пресеты `/raw` и `/strict` сохраняют выбранный способ рассуждения: поле `strategy` в самих
`RAW_OPTIONS` и `STRICT_OPTIONS` существует только ради полноты типа. `/strict` при активном способе
отклоняется целиком — json со способом несовместим.

ESM: `"type": "module"` + `module: "nodenext"`. Top-level `await` используется напрямую.

TypeScript исполняет сам Node, сборщика в дев-режиме нет: `npm run dev` — это `node src/index.ts`.
Типы Node стирает, но пути не переписывает и `./x.js` в `./x.ts` не резолвит, поэтому относительные
импорты внутри проекта указывают на `.ts`, а `rewriteRelativeImportExtensions` возвращает им `.js`
при сборке в `dist/`. `erasableSyntaxOnly` запрещает синтаксис, который стиранием не убирается:
на нём споткнулся `StrategyError` с parameter properties.

Переменные окружения читает `process.loadEnvFile()` в `env.ts`, dotenv не нужен. Отсутствие `.env`
он считает ошибкой — она глушится по коду `ENOENT`, потому что ключ может прийти и из окружения.
Значения окружения файл не перекрывает.

## Особенности reasoning-моделей

`deepseek-v4-flash` пишет рассуждение в `reasoning_content` и только потом ответ. Отсюда четыре
решения, которые иначе выглядят произвольными.

`max_tokens` покрывает рассуждение вместе с ответом, а его длина гуляет от 200 до 2000+ токенов
на одном и том же вопросе. Низкая крышка даёт пустой `content`, а не обрезанный, поэтому
`maxTokens` по умолчанию `null`: длину задаёт `maxWords` через промпт. Крышка осталась явным
флагом `--max-tokens`, её эффект виден по `finish_reason: length`.

Стоп-секвенция сверяется и с текстом рассуждения: если модель упомянет там сам маркер,
генерация оборвётся до ответа. Редко, но случается — `diagnose()` в `index.ts` распознаёт оба
вида пустого ответа и подсказывает флаг.

При `format: "json"` стоп-маркер снимается функцией `dropStopForJson`: `response_format`
уже гарантирует закрытый объект, а маркер после него сломал бы `JSON.parse`.

`temperature` у этих моделей ничего не решает: thinking mode включён по умолчанию, а в этом режиме
DeepSeek игнорирует `temperature`, `top_p`, `presence_penalty` и `frequency_penalty` — принимает
без ошибки, но не применяет (https://api-docs.deepseek.com/guides/thinking_mode/). Поэтому
`DEFAULT_OPTIONS.temperature` — `null`; флаг `--temperature` остался явным, а `temperatureNote()`
в `index.ts` предупреждает, если параметр всё же задали и в ответе было рассуждение.

`--temperature=all` — прогон одного вопроса на `SWEEP_TEMPERATURES` (0 / 0.7 / 1.2) с таблицей
попаданий, уникальных ответов, токенов и времени. «all» разбирается отдельно от числа, как и у
`--strategy=all`; с `--compare` и `--strategy=all` не сочетается — оси перемножились бы. При
включённом thinking mode прогон не отклоняется, а предупреждает: одинаковые колонки и есть
доказательство, что параметр игнорируется, и вторая таблица в `docs/temperature.md`.

Разнообразие считается по значению строки `FINAL:`, поэтому `--temperature=all` включает
`finalLine` и без `--expect`: свободные абзацы дословно не совпадают никогда, и доля уникальных
вышла бы N/N на любой температуре. Отсюда же третий параметр `ensureCompatible` — сообщение о
несовместимости со схемой называет флаг, включивший контракт, а не всегда `--expect`.

`TemperatureTally` считает по извлечённым итогам, а не по заданному эталону: у `--strategy=all`
это одно и то же, у температур — нет, контракт там включён и без `--expect`. Прогон без строки
`FINAL` в знаменатель не входит ни у разнообразия, ни у точности, иначе проза попала бы в множество
ответов как ещё один вариант.

Сделать температуру рабочей может только явное отключение thinking — флаг `--thinking=off`
(`options.thinkingEnabled`, поле `thinking: { type: "disabled" }` в запросе, типов для него в SDK
нет, поэтому в `ask.ts` объявлен локальный тип `DeepSeekParams`). Обе связки не сливаются в одну:
`--temperature` не включает `--thinking=off` сама по себе — каждый флаг делает ровно то, что называет.

## Уровни модели

`models.ts` устроен как `strategies.ts`: реестр без логики. `ModelTier` — пара (модель, thinking),
а не голый id: у DeepSeek только две модели, третьей строки `SWEEP_MODELS` как отдельной модели
не существует — это `flash` с `thinkingEnabled: false`. Слабость этого уровня не предполагается
заранее нигде в коде и в выводе, только показывается таблицей `--model=all`.

`--model=all` не сочетается с явным `--thinking`: thinking уже задан для каждого уровня внутри
`SWEEP_MODELS`, и внешний флаг уравнял бы часть уровней между собой, лишив сравнение одной из трёх
точек. В ветке `cli.allModels` в `index.ts` `thinkingEnabled` берётся из `tier`, а не из общих
`options` — общая строка режима для всех трёх уровней соврала бы про thinking у уровня без него,
поэтому она печатается для каждого уровня отдельно, внутри его секции.

Неизвестный id в `--model` не отклоняется ошибкой, а печатает предупреждение: `KNOWN_MODELS` —
список не закрытый, а опечатка и так проявится понятным 400 при первом запросе.

`ModelTally` разделяет `attempts` и `runs`. Средние по токенам, рассуждению и времени делятся
только на `runs` — прогоны с непустым ответом: иначе быстрый отказ занижал бы и токены, и время
лучшего результата уровня. Оплаченный расход сбоя всё равно уходит в модульный `totalTokens`,
просто не в среднюю цену ответа. Уровень без единого полученного ответа печатает `—`, не `0` —
ноль в этой колонке читался бы как самый дешёвый и быстрый результат.

Пустой `content` у reasoning-модели приходит **без исключения** — `solve()` возвращает результат,
и прогон дошёл бы до `runs` наравне с настоящим ответом. Он считается отдельным счётчиком `empty`
по тому же правилу, что и сбой: расход в `totalTokens` есть, в средней цене ответа его нет,
а колонка `ответов` иначе заявляла бы ответ, которого не было. Потерь у уровня три, и в сноске
они разведены: `сбоев`, `пустых ответов`, `без строки FINAL`.

Рядом с колонкой попаданий (`hits/extracted`, как и у `--temperature=all`) обязательна вторая
колонка со знаменателем от запланированных попыток (`extracted/attempts` либо `runs/attempts`).
Без неё уровень, ответивший один раз из пяти и попавший в цель, показал бы `1/1` и обошёл бы
уровень с четырьмя верными из пяти — пропуск строки `FINAL` у моделей не случаен, слабый уровень
теряет её чаще прочих, и его провалы выпадали бы из метрики первыми.

`--model=all` не включает `finalLine` сам по себе, в отличие от `--temperature=all`: там контракт
нужен и без `--expect`, потому что разнообразие свободного текста иначе всегда было бы N/N.
У моделей разнообразие не измеряется, поэтому третий параметр `ensureCompatible` для этой ветки
не меняется — им по-прежнему заведует только `--expect`.

`OpenAI` клиент в `index.ts` получает `maxRetries` и `timeout` явными числами, хотя они совпадают
со значениями SDK по умолчанию: ретраи на 429 иначе молча увеличивали бы `elapsedMs` уровня,
не попадая в `failures`.
